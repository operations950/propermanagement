How the assistant uses it

Send the key as Authorization: Bearer <key>. Base address: {{ api_base }}/api/v1/

  • GET properties/?q=… — find the property from any part of its name, address, a unit label or the Airbnb/VRBO listing title.
  • GET properties/<id>/?format=text — everything it may know about the property as a ready-to-use document (or without format=text as JSON). Anything not recorded is listed under "Not recorded" so it says so instead of guessing.
  • GET properties/<id>/faq/?q=… — search the FAQ before answering.
  • POST properties/<id>/faq/ with {"question": …, "answer": …, "basis": "host_reply"} — add or correct an entry. Access codes and the wifi password are refused: they live in the access info, so a changed code never leaves a stale copy behind.
  • POST properties/<id>/faq/<n>/used/ — count a use, so you can see which entries earn their keep.

The full reference, with a suggested set of instructions for the assistant, is in BOT_API.md in the code repository. One suggestion above all: let the assistant save an answer only when it comes from something you told a guest (basis: "host_reply") or from the property record — not from what a guest claims — so a guest can't teach it something false.
